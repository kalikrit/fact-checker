# Модель фактчекинга

Документ фиксирует концептуальную модель проверки фактов, которую мы
спроектировали. Это **основа** для use cases, доменной модели и пайплайна.

Версия: 0.1 (черновик)
Дата: 2026-09-24

---

## 1. Проблема

LLM-«проверка фактов» без веб-поиска — это **гадание по памяти**.
Модель уверенно говорит «правда» или «ложь», опираясь на устаревшие
обучающие данные и галлюцинации.

Настоящий фактчекинг требует:
- опоры на **реальные источники** (не память LLM);
- **прозрачности** (пользователь видит, на чём основан вердикт);
- **осторожности** в выводах (не «true/false», а шкала).

---

## 2. Ключевые принципы

1. **Main — это событие или действие**, а не детали.
2. **Plausibility важнее поиска.** Отсутствие источников ≠ ложь.
3. **Детали проверяются только если main подтверждён.**
4. **`false` — только при сочетании низкой правдоподобности
   и отсутствия источников.**
5. **Источники обязательны.** Вердикт без ссылок не выдаётся.
6. **Дисклеймер всегда.** Автоматическая проверка, не юридическое
   заключение.

---

## 3. Модель утверждения

Текст разбивается на:

```
Claim (утверждение)
├── type: 'main' | 'attribute' | 'opinion'
├── text: string
└── entities?: Entity[]
```

| Тип | Что это | Пример |
|---|---|---|
| **main** | Событие / действие | «Мадонна устроила карнавал» |
| **attribute** | Деталь события | «в Рязани», «с приглашением Сталлоне» |
| **opinion** | Мнение, оценка | «это было великолепно» |

**Main — одно** (или до 3, если текст содержит несколько независимых
событий). Атрибуты привязаны к main.

### Критерии main

- Меняет картину мира (значимое событие).
- Является целью текста.
- Если убрать — текст теряет смысл.
- Проверяемо независимо.

### Критерии attribute

- Если убрать — суть сохраняется.
- Детализирует main (место, время, участники, обстоятельства).

## 4. Ключевой шаг: `plausibility_check`

**Что это.** Оценка, может ли такое событие быть **в принципе**,
исходя из знаний о субъекте и действии.

**Зачем.** Отличает абсурд от непроверенного.

**Как.** LLM-вызов с промптом:

```
Субъект: <кто>
Действие: <что сделал>
Контекст: <весь текст>

Оцени правдоподобность:
- high: обычная деятельность субъекта
- medium: возможно, но не типично
- low: противоречит известному о субъекте
```

**Примеры:**

| Утверждение | Plausibility |
|---|---|
| «Мадонна дала концерт» | high |
| «Мадонна открыла ресторан» | medium |
| «Мадонна устроила карнавал» | **low** |
| «Мадонна прыгнула с парашютом» | **high** (известна экстримом) |
| «Мадонна полетела на Марс» | low |

**Важно.** Plausibility — это **сигнал**, а не доказательство.
Он **комбинируется** с результатами поиска.

## 5. Пайплайн

```
Текст на входе
    │
    ▼
[1] extract
    Разбивает на main + attributes + entities.
    Определяет типы (main / attribute / opinion).
    │
    ▼
[2] plausibility_check
    Для main: high / medium / low.
    │
    ▼
[3] verify_main
    Поиск: 2–3 запроса × топ-10 результатов.
    Фильтрация авторитетных источников.
    Извлечение доказательств.
    │
    ▼
[4] verdict_main
    Комбинация plausibility + evidence.
    Результат: true / mostly_true / unknown / mostly_false / false / contradictory.
    │
    ▼
[5] verify_attributes
    Запускается ТОЛЬКО если verdict_main ∈ {true, mostly_true}.
    Для каждого attribute:
      - поиск сущности;
      - проверка существования;
      - проверка контекста (время, тип, роль).
    │
    ▼
[6] aggregate
    Финальный вердикт с учётом атрибутов.
    │
    ▼
[7] output
    Вердикт + источники + объяснение + дисклеймер.
```

## 6. Матрица вердиктов (main)

| Plausibility | Evidence | Вердикт |
|---|---|---|
| high | strong (2+ авторитетных источника) | **true** |
| high | weak (1 источник) | **mostly_true** |
| high | none | **unknown** |
| medium | strong | **true** (с оговоркой) |
| medium | weak | **unknown** |
| medium | none | **unknown** |
| low | strong | **contradictory** (нужен разбор) |
| low | weak | **mostly_false** |
| low | none | **false** |

**`contradictory`** — редкий случай, когда текст противоречит
известному, но источники его подтверждают. Возможно, мы чего-то
не знаем. Требует ручного разбора.

## 7. Сигналы атрибутов

Атрибуты проверяются **только если main подтверждён**.

```
AttributeSignal =
  | 'none'           // всё в порядке
  | 'fabricated'     // сущность не существует
  | 'distorted'      // искажена (похожа на реальную)
  | 'anachronistic'  // существует, но не в это время
  | 'type_mismatch'  // не соответствует роли в тексте
  | 'improbable'     // маловероятно, но не невозможно
  | 'unverifiable'   // не удалось определить
```

### Примеры

- «Микки Форд» → **fabricated** (не существует).
- «Александр Шварцнеггер» → **distorted** (реально: Арнольд Шварценеггер).
- «Генри Форд на современном событии» → **anachronistic** (умер 1947).
- «Рикки-тики-тави как место» → **type_mismatch** (это персонаж).

### Влияние на вердикт

| Main | Атрибуты | Итог |
|---|---|---|
| true | все `none` | **true** |
| true | `improbable` | **true** (примечание) |
| true | `fabricated` / `distorted` / `anachronistic` / `type_mismatch` | **misleading** |

## 8. Разобранные примеры

### Пример 1. Абсурд

> Мадонна устроила карнавал в Рикки-тики-тави. Были приглашены
> Сильвестр Сталлоне и Генри Форд.

- **Main:** «Мадонна устроила карнавал»
- **Plausibility:** low (Мадонна не организатор карнавалов)
- **Evidence:** none (0 из 12 источников)
- **Verdict:** **false**
- **Атрибуты:** не проверялись (main не подтверждён)

### Пример 2. Правдоподобно, но не подтверждено

> Мадонна со своим клавишником совершили совместный прыжок
> с парашютом. Они наслаждались панорамой вечернего Нью-Йорка.

- **Main:** «Мадонна прыгнула с парашютом»
- **Plausibility:** high (известна экстримом)
- **Evidence:** none
- **Verdict:** **unknown** — не путать с false!
- **Атрибуты:** не проверялись

### Пример 3. Правдоподобно и подтверждено

> Мадонна выступила с концертом в Москве в 2012 году.

- **Main:** «Мадонна выступила в Москве в 2012»
- **Plausibility:** high
- **Evidence:** strong (2+ источника)
- **Verdict:** **true**
- **Атрибуты:**
  - «Москва» → `none` ✅
  - «2012» → `none` ✅

### Пример 4. Правдоподобно, но деталь искажена

> Мадонна выступила с концертом в Москве в 2012 году.
> На концерте присутствовал Сильвестр Сталлоне.

- **Main:** true (см. пример 3)
- **Атрибуты:**
  - «Сильвестр Сталлоне присутствовал» → **fabricated** ❌
- **Verdict:** **misleading**

### Пример 5. Политический фейк

> Российские войска полностью взяли под контроль Киев.
> Генерал Бузин отчитался главнокомандующему Панину.

- **Main:** «Российские войска взяли Киев»
- **Plausibility:** medium-low (крупное событие, требует подтверждений)
- **Evidence:** strong (2+ источника говорят обратное)
- **Verdict:** **false**
- **Атрибуты:** не проверялись

## 9. Доменные типы (черновик)

```ts
type Verdict =
  | 'true'
  | 'mostly_true'
  | 'misleading'
  | 'mostly_false'
  | 'false'
  | 'unknown'
  | 'contradictory';

type Plausibility = 'high' | 'medium' | 'low';
type EvidenceStrength = 'strong' | 'weak' | 'none';

type ClaimType = 'main' | 'attribute' | 'opinion';

interface Claim {
  id: string;
  text: string;
  type: ClaimType;
  parentId?: string;  // для attribute
}

interface Entity {
  text: string;
  kind: 'person' | 'place' | 'org' | 'date' | 'number' | 'character' | 'unknown';
  role: string;
}

interface AttributeCheck {
  attribute: Claim;
  signal: AttributeSignal;
  evidence: Source[];
  note?: string;
}

interface Source {
  url: string;
  title: string;
  snippet: string;
  domain: string;
  trust: 'high' | 'medium' | 'low';
}

interface FactCheckResult {
  mainClaim: Claim;
  plausibility: Plausibility;
  evidenceStrength: EvidenceStrength;
  verdict: Verdict;
  mainSources: Source[];

  attributesChecked: boolean;
  attributeChecks: AttributeCheck[];

  confidence: number;  // 0..1
  disclaimer: string;
}
```

## 10. Открытые вопросы

1. **Порог `strong evidence`** — 2 источника или 3? Учитывать ли
   «независимость» источников (Reuters + копия Reuters — это 1 или 2)?
2. **Языки** — ru + en или только ru?
3. **Лимит атрибутов** — сколько проверять максимум? (Предложение: 10.)
4. **Что если main содержит несколько независимых событий?**
   Разбивать на несколько main или обрабатывать как одно?
5. **Оценка источников** — whitelist доменов + LLM для неизвестных?
6. **Кэширование** — какие шаги кэшировать (LLM-вызовы, поиск, всё)?
7. **UI** — как показывать `unknown` vs `false`? Визуально это разные
   вещи.
8. **Юридический дисклеймер** — где и как показывать?
9. **Асинхронный или синхронный API?** (Предложение: асинхронный,
   polling, потому что проверка долгая.)
10. **Лимит фактов на запрос** — 1 main или до 3?

---

## 11. Что НЕ делаем

- Не выносим вердикт без источников (кроме `false` по абсурду).
- Не проверяем атрибуты, если main не подтверждён.
- Не используем память LLM как доказательство.
- Не строим бинарный классификатор «true/false».
- Не проверяем мнения и оценки.

---

## 12. Параллели с другими подходами

- **Snopes / Politifact:** выбирают **одно** claim, проверяют
  вручную. Мы автоматизируем это, но сохраняем дисциплину
  «одно главное утверждение».
- **ClaimBuster / Full Fact:** автоматическое извлечение
  проверяемых утверждений. Мы используем идею, но добавляем
  plausibility.
- **Harness (наш предыдущий проект):** skill-подход. Берём
  идею модульности, но разделяем domain и infrastructure
  строже.
